## Test design snapshot

Founder tries one available connected assistant over two or three natural meal decisions. Connect through web then use Android; check actual connector use. Ask for three specific dishes/outlets within the real budget/preferences, sourced links, and clearly qualified prices. Do not place an order through this research. Open links and classify exact dish, restaurant menu, homepage, wrong or broken destination; measure remaining search and choosing effort. Record setup failures separately.

After an independently chosen meal, supply honest feedback. On a later new conversation, test whether that correction improves the next suggestions. Return setup outcome, actual responses/link destinations, appeal, effort, corrections and willingness to return. Skipped occasions and no orders remain valid observations. This is exploratory personal evidence, not a prevalence or payment test. [Current instructions and prompt](../tests/T001-existing-alternatives.md#android-founder-trial).

If setup removes the complaint, examine onboarding value or use the existing product. If consequential failures recur, identify whether they arise from data access, linking, recommendations or memory before comparing with friends. A commercial build remains undecided.
