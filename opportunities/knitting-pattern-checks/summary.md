# Knitting pattern checks

We would sell software to people who check knitting instructions before a designer publishes them. These specialists, called technical editors, check that the steps, diagrams and numbers of stitches agree for every garment size.

The proposed tool would help them follow complicated changes in stitch counts. It would show where a calculation appears wrong, explain the calculation and identify instructions it cannot interpret. The editor would review the results and decide what needs correcting.

## An example

**Imagined example:** An editor is checking a sweater pattern with several sizes. In one size, the instructions start with 120 stitches, add two stitches four times, then say there should be 126 stitches.

1. The editor imports the draft in a supported format.
2. The tool follows that size's instructions and flags the mismatch: 120 + 2 × 4 = 128.
3. It points to the relevant lines so the editor can correct the draft. If an instruction has more than one possible meaning, the editor must resolve it.

This is a simplified illustration of the intended check. A working product would need to handle the more complicated instructions that editors actually spend time checking. It has not been built or tested.

## Who would pay, and for what?

An editor or editing business could pay for a software license, possibly per user or per year. A designer could instead pay per pattern release. These are possible models; the choice, price and payment terms are unset ([proposed offer](research.md#c003)).

The intended buyers are professionals publishing or checking patterns repeatedly. Complaints from people who buy knitting patterns do not establish that those professionals would buy this software.

## What the research tells us

Knitters report incorrect counts and disagreements between diagrams and written instructions. Those accounts support the existence of mistakes, but provide weaker evidence about repeated work that professional editors cannot handle satisfactorily ([problem accounts](research.md#c001)).

Stitchwright already checks written instructions across sizes, and Stitchmastery checks diagram counts. Editors also use spreadsheets and paper successfully. One competitor lists limits on several complicated types of instruction. That suggests a question worth investigating, without proving that editors need another tool ([existing alternatives](research.md#c002)).

## What delivering it would take

We would need an experienced editor and permission to use real drafts with known corrections. The software must interpret instructions accurately, keep separate calculations for each size and show which sections it has checked. An unread instruction cannot count as a successful check.

Development, expert review and support costs are unknown. Existing free and paid tools may limit what buyers would pay ([delivery and costs](research.md#c003)). Public editor and designer directories offer a way to look for suitable people; no willing expert or buyer has been found ([customer access](research.md#c004)).

## The next useful check

The existing recommendation puts this second among the three newer ideas, provided we can work with an experienced editor. Compare their normal method and existing tools on the same complicated draft.

The key question is: **does a costly, repeated checking task remain that an editor would pay us to help with?**
