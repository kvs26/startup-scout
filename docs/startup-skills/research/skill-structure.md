# How to structure the startup skills

Research note, 15 October 2026. Question: should all instructions live in `SKILL.md`, or should the skill folder contain supporting files?

## Findings from primary sources

1. **A folder with one entry point is the documented format.** The [Agent Skills specification](https://agentskills.io/specification) requires a `SKILL.md` with `name` and `description` in YAML frontmatter and permits other files and directories. `scripts/`, `references/`, and `assets/` are recommended conventions, not required names. The specification has no fixed body format. [OpenAI's Codex documentation](https://learn.chatgpt.com/docs/build-skills) describes the same folder shape.

2. **The loading order favors a short entry point.** [Codex documentation](https://learn.chatgpt.com/docs/build-skills) says name and description are available for discovery, the full `SKILL.md` loads when selected, and supporting resources are optional. The [Agent Skills specification](https://agentskills.io/specification) recommends a main file under 500 lines and instructions under 5,000 tokens; these are recommendations, not validation limits. It advises focused reference files, paths relative to the skill root, and avoiding deep chains of references.

3. **Keep the working contract in `SKILL.md`.** [OpenAI's Skills guide](https://developers.openai.com/api/docs/guides/tools-skills) says to keep the main instructions there and link to supporting files. [OpenAI's plugin authoring guide](https://developers.openai.com/plugins/build/skills) says the entry point should identify inputs, steps, outputs, facts the agent must not infer, stop/ask conditions, and which files to consult. It recommends `references/` for detailed policies, schemas, examples, and background; `assets/` for reusable templates; and `scripts/` for deterministic processing. The entry point should say *when* to read or run each file.

4. **Route by task, not by a compulsory reading list.** In [OpenAI's current skill-writing guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), a skill with multiple workflows can use a minimal root router to relevant documents and scripts. Loading every reference for every request consumes context and may bring in irrelevant instructions. [Anthropic's Claude Code guidance](https://code.claude.com/docs/en/skills) independently recommends linking supporting files by purpose and reading them when needed. This is a shared design recommendation across those products; it is not a universal industry rule.

## Application to this repository

The current [scout entry point](../../../.agents/skills/startup-idea-scout/SKILL.md) is 85 lines and about 2,100 words. It is below the specification's suggested 500-line ceiling, yet every activated run still reads its entire body. It also directs the agent to read three shared guides at the start. Shortening or routing those instructions may be more valuable than moving text merely to meet a line count. This is an inference from the documented loading behavior and a local file inspection, not a measured performance result.

For the scout, keep its trigger, the one-idea scope, entry paths, core evidence and honesty rules, required deliverable, and a short checklist for a decision-ready summary in `SKILL.md`. Keep the existing cross-skill material under `docs/startup-skills/` when scout, investigator, and customer connect share it. Add `references/` inside the scout folder only for scout-specific detail that a particular path needs. For example, a `references/domain-learning.md` could hold detailed interview and learning guidance, and a `references/summary-quality.md` could hold the expanded writing review. Link each from the root with a condition such as “Read this when writing a summary.” Templates belong in `assets/` only if they are skill-specific; the existing shared templates can remain under `docs/startup-skills/templates/`. Add `scripts/` only if a repeatable operation genuinely needs code.

The next revision should first identify which material every scout run needs and which material applies only to open discovery, a supplied idea, continuation, or summary writing. Move only the latter to focused files. Check that paths work and try representative requests from each path; [OpenAI recommends](https://developers.openai.com/plugins/build/skills) testing direct, indirect, incomplete, nonmatching, and edge-case requests. A shorter file alone does not establish that the skill will follow instructions better.
