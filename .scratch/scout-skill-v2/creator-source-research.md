# YouTube and Instagram creator sources for scout version 2

Research date: 2026-10-28 (Asia/Kolkata). Owner: creator research subagent. Related decision: [Research YouTube and Instagram creators as discovery sources](issues/02-research-creators.md).

## Finding

Creator content is useful for **discovering names, workflows and business models**, including gigs and small businesses that startup directories miss. It is not independent validation of a business's earnings or demand. A workable initial mix combines Indian business explainers, international founder interviews, bootstrapped software communities and a small number of idea brainstormers. Prefer original companion articles and show notes where video extraction is unreliable. Keep Instagram as a selective discovery route until particular profiles/posts can actually be read.

This is source-selection research, not a channel endorsement or a completed idea assessment. No videos were watched or listened to; no full original video transcripts were retrieved. The findings below distinguish source-owned pages, indexed video metadata and inaccessible originals. Commercial relationships mentioned below are those visible on source-owned pages, not allegations about undisclosed arrangements.

## Access methods: what is actually established

| Need | Verified route | Limits / readiness |
| --- | --- | --- |
| Find YouTube videos/channels | Public search and indexed original descriptions worked for some examples. Google's [Data API overview](https://developers.google.com/youtube/v3/getting-started) documents a Cloud project, enabled API and credentials; public retrieval methods exist. | API capability is documentation-verified, not exercised here; no account/key was created. Metadata is not the video's spoken content. |
| Filter or monitor a channel | [search.list](https://developers.google.com/youtube/v3/docs/search/list) supports channel, query, dates and caption-availability filters; its documentation recommends the uploads playlist with playlistItems.list for reliable recent channel uploads. | Search can be incomplete. `regionCode` concerns availability in a country, not creator nationality or an idea's market. Recheck live quotas rather than hard-code an old quota model. |
| Read spoken text | YouTube's [Show transcript instructions](https://support.google.com/youtube/answer/15930243) document the public UI when captions exist; timestamp lines can navigate to the relevant passage. Original creator articles/show notes are another route. | Documentation verified; transcript UI not tested in this run. Transcription/translation errors can change rupees/dollars, names, revenue/profit and dates. A transcript cannot establish what a visual chart actually shows. |
| Download caption tracks by API | Official [captions.download](https://developers.google.com/youtube/v3/docs/captions/download) explicitly requires OAuth authorization and **permission to edit the video**. | This is not a general public transcript API for arbitrary creators. Do not promise that obtaining an ordinary API key solves third-party transcripts. |
| Inspect visual or audio evidence | Open a permitted original video/reel in the available browser and inspect the relevant segment where supported. Record the timestamp and the modality actually reviewed. | No such inspection was performed here. A creator showing a dashboard still supplies a creator-provided exhibit, not an audit. Browser automation helps interact with UI; it does not grant permissions or guarantee transcript access. |
| Read Instagram programmatically | [Meta's official Postman team](https://www.postman.com/meta) links its [Instagram API collection](https://www.postman.com/meta/instagram/collection/6yqw8pt/instagram-api). The collection describes professional accounts and a Facebook App plus user access token. | Confirms an official authenticated API exists. This does **not** establish access to arbitrary creators, all reels, spoken transcripts or a general keyword-discovery feed. No live API call was made. |
| Instagram Business Discovery | [Official guide](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/business-discovery) returned 429; [reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery) was inaccessible. | Exact current permissions, target-account constraints and usable fields remain unverified. Evaluate only after current official docs and an authorized test are available. Do not implement from third-party snippets. |
| Public Instagram posts | Try original permalink/profile through ordinary reading or an available browser; follow creator-owned cross-posts/newsletters when access fails. | Both sampled Instagram profiles failed. No public transcript endpoint verified. Mark coverage missing and continue; do not count an inaccessible reel as read. |

Playwright is not the only option. Public reading, source-owned articles, official show notes and YouTube metadata APIs cover different parts of the job. A browser is a fallback for interaction, especially Show transcript and specific reels. An automation implementation should be chosen only after the source mix is agreed.

## Proposed free/public-first workflow

1. Assign a creator-source subagent a bounded mix: an Indian operator/explainer, an international software source and a small-business/gig source where relevant. This is a proposal, not an agreed mandatory quota. Its output must distinguish candidates found from candidates substantively inspected.
2. Discover from original channel metadata, creator-owned show notes, indexed descriptions and links supplied by the user. Store the original URL, creator/channel, content date if known, accessed date, geography and retrieval state. Avoid an exhaustive crawl.
3. For promising candidates inspect the relevant primary passage using available text/transcript and, when necessary, audiovisual evidence. Record whether the evidence was metadata, creator-written text, captions, audio, or visuals. Use `not inspected` for missing modalities. Do not silently promote an aggregator's AI summary to an original transcript.
4. Extract the business name, buyer, problem, offer, price/financial claim with period and currency, delivery mechanism and named references. Preserve “creator estimates,” “guest reports” and “host proposes” separately from facts checked elsewhere.
5. Follow the lead to the actual business: live product/pricing, customer documentation, original founder reports, regulatory/public filings where applicable, buyer discussions and competitors. Distinguish company-authored claims from independent customer evidence. If the business cannot be identified, keep a speculative lead and lower confidence.
6. Dedupe by underlying business/customer problem and canonical original episode. A reel, its full episode, a newsletter recap and five copycat clips do not make seven independent sources. Look for identical numbers, anecdotes, screenshots, wording and destination links. Group creator-owned businesses and promotional affiliates as related provenance.
7. Note visible paid-partnership disclosures, sponsor reads, course/community offers, affiliate links and portfolio involvement. Missing disclosure is `unknown`, not proof of neutrality or misconduct. Repeated earnings claims without costs, period, refund rate or the underlying business are reasons to seek better evidence.
8. For India adaptation, separately check local alternatives, affordability, labor/capital differences, distribution and customer workflow. “Works in the US” and popularity of a creator are discovery cues, not local validation. Preserve current technology eligibility until the user changes it.
9. Pass deduplicated leads plus original citations, observed access limits and proposed scale rationale to the parent scout. The parent performs comparative assessment under the agreed rules; creator-source results must not inflate the count of deeply assessed ideas.

## Gaps and next decision

This run establishes several useful source-owned content routes and official YouTube access constraints. It does not establish a complete Instagram portfolio, live API integration, latest-episode completeness, original-video transcript retrieval, or the truth of any earnings claim. Some samples are historical by design; they establish source type, not current business opportunity.

Suggested next owner: the source-selection decision with the user. Choose a small rotating creator panel from the stronger candidates, decide whether gigs/offline small businesses are eligible or merely workflow inspiration, and decide whether Instagram should be an optional best-effort lane while access is unverified. If Instagram becomes mandatory, create a separate authorized access-validation task rather than silently substitute third-party summaries. No change to the scout skill has been made by this research.
