# API, feed and export access for scout version 2

Checked 2026-10-28. Resolves the factual investigation in [Research available APIs, useful coverage and access costs](issues/08-research-api-access-costs.md). **Initial total paid-research planning cap: ₹1,000/month**, supplied by the user during this investigation. No subscriptions, credentials, account settings or integrations were changed.

## Finding

Inventory every available route, but connect them in stages according to entitlement, useful coverage and total cost. The practical first tests are the official HN API, YouTube metadata, existing Tavily access and SaaSHub product/alternatives lookup after checking its account terms. Keep approval-based, quote-only and expensive APIs in the inventory rather than pretending they are either connected or nonexistent. No paid company database here is verified within the ₹1,000 total cap.

This covers all **28 website entries** in the [original report](2026-10-28-discovery-websites-research.md), plus the creator platforms and existing supporting tools. Findings below supersede narrower access claims where explicitly noted. “Not verified” means the investigation did not establish a supported route; it does not prove no arrangement exists. Official documentation is not a successful runtime call. API prices exclude unspecified taxes, foreign exchange/card fees and other subscriptions.

## Creator platforms and original-site routes

**YouTube:** Official Data API supports channels, videos, playlists and comments with a Google project and API credentials; public metadata does not require acting as the creator. The official [overview](https://developers.google.com/youtube/v3/getting-started) describes quota rather than a per-call paid tariff. Current [quota table](https://developers.google.com/youtube/v3/determine_quota_cost), updated October 15, 2026, gives a separate 100-search-calls/day bucket and 10,000 units/day for other endpoints; ordinary channel/playlist/video reads cost one unit. Do not copy older “search costs 100 shared units” examples into the implementation. Confirm actual project quota before a run. No YouTube API call was performed here.

Use channel uploads playlists for known creators and selective search for discovery. **This retrieves metadata, not arbitrary transcripts.** Official [caption download](https://developers.google.com/youtube/v3/docs/captions/download) needs OAuth and permission to edit that video; buying metadata access does not grant that permission. For others' videos, use available public [transcript UI](https://support.google.com/youtube/answer/15930243), source-owned show notes/articles, or user-supplied transcripts/screenshots with original URL and timestamps. Visual claims need relevant frames. No third-party transcript vendor was evaluated or priced in this bounded inventory.

**Instagram:** Meta's [official collection](https://www.postman.com/meta/instagram/collection/6yqw8pt/instagram-api) establishes an authenticated professional-account API. Its [Facebook Login documentation](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-00dab679-d4c0-4957-bed0-0bcda896be09) describes linked professional account/Page access, hashtagged media and basic metadata/metrics about other business/creator accounts; consumer accounts are excluded. The collection covers several operations, so its combined permission list is not a minimal read-only scope specification. Exact Business Discovery field/approval entitlement, quotas and costs still need a scoped test. Do not assume it supplies arbitrary reels, full spoken transcripts or general keyword search. No live call was made; public original posts, browser, creator sites and user-provided slides/captions remain fallbacks.

**Creator websites and podcasts:** the [creator report](creator-source-research.md) identifies original sites/show notes for the ten named candidates. No distinct creator API or podcast RSS feed was verified there. Check a feed linked by the actual show when monitoring becomes necessary; do not invent a `/feed` endpoint or equate an audio enclosure with a transcript. The platform inventory above serves all these creator candidates; it does not multiply subscriptions by creator.

## Existing supporting access and cost model

[SETUP.md](../../SETUP.md) records Tavily search/extract/map/crawl authentication and configured VS Code process checks from October 10. This is historical evidence, not a fresh test in this session. Configured keys were not read or printed. Hunter/Apollo are contact aids with recorded plan/connection limits; they do not replace this source inventory and need no paid upgrade for the current scout task.

[Tavily pricing](https://docs.tavily.com/documentation/api-credits), rechecked here: 1,000 included credits/month; PAYG $0.008/credit; smallest monthly paid plan $30 for 4,000 credits. Basic search costs 1, advanced search 2; five successful basic URL extractions cost 1 credit (advanced: 2). Crawl combines mapping and extraction charges. The existing setup leaves PAYG-off status unconfirmed. Recheck balance and billing before calling paid operations; this research did not activate PAYG.

Hypothetical monthly workload: **200 basic searches + 250 successful basic extractions in batches of five = 250 credits**. That fits 1,000 included credits only if enough remain after other users/tasks; it is an access-cost example, not a claim that it completes fifty deep assessments. Another 500 chargeable credits at PAYG would cost $4. A planning-only exchange assumption of ₹90/$ plus a 20% combined FX/tax/fee buffer gives **₹432**; actual bill may differ. At those assumptions 1,000 chargeable credits cost ₹864, leaving little room for other services. Neither figure is permission to enable uncapped billing. The $30 plan models as ₹3,240 and fails the ₹1,000 cap.

YouTube example: monitoring ten known channels with ten channel lookups, ten upload-playlist pages and ten video-detail requests uses approximately 30 ordinary quota units; 20 separate discovery searches use 20 calls from the search bucket. Pagination and extra comments add work. This estimate covers metadata only and does not assume a paid route to more quota.

Budget implication: begin with included/public routes; reserve any paid allowance for a demonstrated retrieval gap. ₹1,000 is a combined monthly cap, not per provider. Unknown-quote APIs cannot be marked affordable. Inc42 already exceeds it before tax; Exploding Topics is far beyond it. SaaSHub and approval-based BetaList/Product Hunt need actual terms before any budget commitment.

## Connection sequence and acceptance checks

1. **Verify reusable/public access:** confirm Tavily allowance/billing and actual client availability; test HN list plus one original item/comment. Repair XML-capable feed reading if Trend Hunter is chosen. Record real returned fields and errors.
2. **Add practical account APIs:** YouTube metadata with project quota and read-only intent; SaaSHub after price/quota/attribution review. Test one known record and a bounded list before marking connected. Protect query-string keys from logs where a provider requires them.
3. **Track restricted options explicitly:** Product Hunt business-use clearance, BetaList access request, Google Trends alpha and Instagram scoped permissions. This report authorizes none of those submissions; record pending rather than fake a working connection.
4. **Retain commercial options:** quote-only Dealroom/Crunchbase/Tracxn/Springwise and priced exports/APIs remain catalogued with current cost and access status. Revisit when a concrete unmet need and revised budget justify it.
5. **Use agreed fallbacks:** ordinary web → interactive browser where needed → targeted user screenshots/paste/export. Ask for original URL, date, relevant caption/slides and timestamp; identify omissions and do not claim full-source review. Source-specific reuse limits still apply.

For every connection record capability (metadata/full text/exports), entitlement, monthly allowance, marginal price, renewal/overage behavior, test date, successful sample and fallback. Proposed catalog adapters are not running integrations. Update the setup record only after observed tests.
